# Contributing to HolyMind

Thank you for your interest in contributing to HolyMind! We welcome improvements, bug fixes, and new features from the community.

## How to Contribute

### 1. Fork and Clone

Clone the HolyMind repository locally to develop your improvements:

```bash
git clone https://github.com/EnzoHashinokutiXavier/HolyMind-V1-Reduced-Version.git
cd HolyMind
```

### 2. Create Your Adaptation or Improvement

You are free to modify and improve the code according to your needs. All modifications must comply with the [LICENSE](LICENSE) terms:

- **Non-Commercial Use Only**: Your version must not be used for commercial purposes or to generate any form of revenue
- **Brand Protection**: You cannot publish or present your version as the official HolyMind project without authorization
- **Attribution**: You must maintain attribution to the original creators

### 3. Submit Your Changes to the Official Project

If you believe your improvements would benefit the HolyMind community, you can request to have your version incorporated into the official repository:

#### Option A: Pull Request (Recommended)

1. Push your improvements to your fork
2. Create a **Pull Request** to the main HolyMind repository
3. Describe your changes, their purpose, and any testing you've done
4. The maintainers will review your contribution and decide whether to merge it

#### Option B: Request a Dedicated Branch

If your adaptation is substantial and you'd like to maintain it as a separate branch within the official repository:

1. Document your changes thoroughly
2. Contact the maintainers (see "Contacting Maintainers" section below)
3. Explain your use case and why a dedicated branch would be beneficial
4. The maintainers will evaluate your request and may create a named branch for your version

### 4. Contribution Guidelines

When submitting contributions, please ensure:

- **Code Quality**: Your code should be clear, well-commented, and follow the project's existing style
- **Testing**: Test your changes thoroughly before submitting
- **Documentation**: Update README or other docs if your changes affect user-facing features
- **License Compliance**: All contributions must comply with the PolyForm Noncommercial License
- **Attribution**: Give credit to any external libraries, resources, or inspirations you've used
